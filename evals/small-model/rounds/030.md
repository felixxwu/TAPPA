## All four predictions were confirmed on OUTCOME — and prediction 2's REASONING was wrong

This is the round's most useful result, and it only shows up because I checked the mechanism rather than ticking
the outcome.

I predicted `features/rendering.md` would be missed **because the probe would only read** `speed_lines_setting.gd`.
It **edited** that file — and still left `rendering.md` untouched. So "the pointer has to be in a file you edit"
is refuted as a sufficient condition, and a confirmed prediction would have hidden that if I had stopped at the
tick.

**What actually separates the two docs is the WEIGHT of the change in the file that names them:**

| doc | named by | that file's change | doc updated? |
|---|---|---|---|
| `features/settings.md` | `settings_menu.gd` | **~30 lines of real work** | **yes** |
| `features/rendering.md` | `speed_lines_setting.gd` | **2 comment lines** | no |

> **Refined from round 029: doc effort follows the weight of the change PER FILE, not the size of the change
> overall and not whether the file was touched at all.** That also explains round 029 (four files each moderately
> changed, attention spread thin, zero docs) without needing a separate story.

## And the cleanest evidence yet for "contradiction beats reference" — inside one probe

The same probe, in the same run:

- **Fixed a falsified statement** in a file it edited: `speed_lines_setting.gd` said "adding the player-facing
  menu row is deliberately **NOT** done here; only the seam exists so far". Its change made that false, and it
  rewrote the sentence unprompted.
- **Ignored a reference** in the very same file: that file's `# Docs:` breadcrumb names `features/rendering.md`,
  and the doc went untouched.

Two lines apart, same file, same probe, opposite outcomes. That is the tightest controlled contrast the loop has
produced on this question:

> **A statement the change makes FALSE, sitting in the file being edited, gets fixed. A POINTER to a file that
> should change does not.** Round 014 found the first half; round 019 and round 029 kept failing to move the
> second. This round shows both halves simultaneously, which rules out probe-to-probe variance as the
> explanation.

**Actionable consequence, and it redirects the loop's docs strategy:** stop trying to make a pointer work. Put
the *claim* where the editor is working — probes reliably repair contradicted claims — and enforce genuine
cross-file doc obligations with a **machine guard** (round 017's tyre-doc guard is the working example). Notes and
breadcrumbs are for humans; they do not move a small model to another file.
