## Failure causes observed

1. **Hidden coupling across files (×4, dominant — REPEAT of round 001's top cause).**
   T001: a grip field must be *consumed* by `drivetrain.gd`/`lap_time_model.gd`, not just
   declared. T003: a region is only reachable via a rally's `region` tag. T004: the gear
   label's startup state is pinned by a test three files away. T008: end-of-rally HP is
   post-repair and is not a damage record; the star payout is pinned exactly.
2. **Unclear which tests cover the area (×4, universal).** Every probe read the correct
   `features/` doc. None found the tests that owned the behaviour it was changing — 4 docs
   named no test at all, and the 64 that did buried the mention hundreds of lines down
   (`regions.md` at line 523 of a 530-line file).
3. **Convention undiscoverable at the point of use (×3).** T008 hardcoded a star amount
   with no sibling `@export` to pattern-match and no comment at the site; T004 skipped the
   mandatory-test rule; T006 had no sense of scale at the knob it turned.
4. **`features/` entry stale, misleading, or incomplete (×2).** `reward-system.md` and
   `reward_system.gd`'s own header actively disclaim owning *when* a reward fires, routing
   T008 away from the rubric's expected home. `regions.md` described what a region *is*
   but never that a rally tag is required to ship one.
5. **NEW — one fact duplicated across docs with no pointer (×1).** The rock-density
   ranking is asserted in both `regions.md` and `rocks.md`; T003 corrected one and left
   the other stale. Added to the taxonomy.

### The round's sharpest finding

**Round 001's fix worked and was not enough.** Its guard made "the effect writes a name
nobody declares" go red. T001's probe therefore *declared* `tire_gravel_grip_mult`, the
guard went green, and the part was still completely inert — the physics never reads that
name. Existence is not consumption. This is precisely the repeat-across-rounds evidence
§2.6 asks for before escalating, so this round's grip fix adds the consumption half.

## Fixed this round (main checkout)

Three causes, by frequency × cost.

### Fix 1 — "unclear which tests cover the area" (cause 2, ×4)

Every `features/*.md` area doc (67 files) now carries a **`**Tests:**`** line in a fixed
position, immediately under its `**Source:**` line, naming the `tests/headless/test_*.gd`
files that cover it. Every named path was verified to exist; none needed the
"no coverage" fallback. `features/README.md` states the convention.

New `tests/headless/test_features_docs.gd` (4 tests) enforces it: every area doc has a
`**Tests:**` line, every path it names exists, every doc is linked from
`features/README.md` (that last one also guards round 001's universal "forgot to index
the doc" failure), plus a guard that the folder scan itself isn't vacuous.

- **Layer 1 (authoring):** yes — it is in the first screenful of the doc the model
  demonstrably reads first, in the same place in every file.
- **Layer 2 (runtime):** N/A — markdown does not execute. Stated rather than skipped.
- **Layer 3 (test):** yes — `test_features_docs.gd` goes red on a missing line, a
  dangling test path, or an unindexed doc.

### Fix 2 — grip fields declared-but-inert (cause 1; escalation of round 001's fix)

- `tests/headless/test_upgrade_library.gd` →
  `test_every_grip_feeding_effect_field_is_read_by_the_physics`: every `feeds_grip`
  effect field that is a `GameConfig` property must be *mentioned* in one of the three
  grip readers (`drivetrain.gd`, `lap_time_model.gd`, `car_performance.gd`). A source-text
  check, because nothing else can distinguish "read" from "declared". Pins no value, names
  no catalogue entry, iterates `EFFECTS` as opaque input.
- Point-of-use note on `game_config.gd`'s `tire_snow_grip_mult` / `tire_tarmac_grip_mult`
  block: this is a **closed pair**; `tire_surface_mult` takes exactly two multipliers, and
  a third surface axis means changing that function, its call sites in `drivetrain.gd`,
  `car.gd::_apply_physics_spec`'s reset and `car_performance.gd::merged_meta`'s carry
  list. An extra `@export` alone compiles, applies, and does nothing.
- **Layer 1:** yes — the note sits exactly where the probe added its export.
  **Layer 2:** skipped, with reason — "is this property ever read" is not a runtime-
  knowable fact; `UpgradeLibrary._cfg_set` (round 001) already covers the runtime half
  that *is* knowable (a write to a non-existent property). **Layer 3:** yes.

### Fix 3 — region reachable only via a rally tag (cause 1 / cause 4)

- `tests/headless/test_region_assets.gd` →
  `test_every_region_is_reachable_from_at_least_one_rally`: the reverse of the existing
  rally→region check. Two authored tables must agree; pins nothing about either.
  Verified valid against the shipped data (all 6 regions are claimed today), and it is
  exactly what T003's change would have tripped.
- Point-of-use note on `RegionLibrary.REGIONS` ("adding a region is TWO edits") and the
  same statement near the top of `features/regions.md`.
- **Layer 1:** yes, at the table the probe edited and in the doc it read.
  **Layer 2:** skipped — an orphan region is inert rather than erroneous, and a
  `push_error` at catalogue load would fire in every synthetic-region test.
  **Layer 3:** yes.
