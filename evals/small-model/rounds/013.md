### What the evidence actually supports

Round 010 is the discriminating data, and I had it all along: **two of that round's five probes DID
update a `features/` doc** unprompted (T009 → `drivetrain-and-tires.md`, T006 →
`engine-and-transmission.md`). So "probes don't write docs" is false. The difference:

> **A probe updates the doc it had to READ. It does not update a doc it never opened.**

T009 and T006 had to open their area doc to understand the system they were changing, and edited
it while they were there. T002's probe never needed to: `menu_nav.gd`'s inline comment block
documents `remember` completely — its default, its fallback semantics, the hidden-sub-panel rule.
The probe read the code, understood it fully, and had no reason to open `menu-navigation.md`.

**Round 012 made the code self-documenting enough that the doc became unnecessary to read — and
therefore unnecessary to write.** That is an uncomfortable finding, because the point-of-use
comment is a thing §3 explicitly recommends, and rounds 009–010 credited named seams with the
biggest wins in this loop's history. It suggests the two goals genuinely trade against each other
at the margin, which no round has said before.

### Fix 1 — deduplicate the seam's comment so using it requires opening the doc

`menu_nav.gd`'s `remember` entry was a **nine-line block that documented the feature completely**:
default, fallback-to-`first`, the hidden-sub-panel rule, and the "don't hand-roll it" warning. It
duplicated `features/menu-navigation.md` → "Remembering the selected row" almost exactly. §2.6
says to count the comment lines you add and delete what your addition makes redundant; I wrote
that block in round 011 and did not apply the rule to myself.

Now seven lines: what the flag does, off-by-default, never hand-roll it — and then the fallback
rules and *what else a menu change owes (docs + a nav test)* live only in the doc, with a pointer
and an instruction to read it before turning the flag on.

**Layers.** Layer 1 partially: the information needed to use the flag correctly no longer exists
at the call site, so the correct route now passes through the doc. Layer 3: none new — deliberate,
see below.

**Durability — NEITHER a sweep nor a ratchet. This is an EXPERIMENT, and I am labelling it as one
rather than letting it pass as a fix.** Nothing enforces it and nothing carries it to the next
seam. It exists to test one falsifiable claim.

**§D4 generalisation.** The change is to the framework's opts documentation, which serves every

### What is left, and why this loop cannot fix it

Round 008 already wrote the remaining explanation and I have now spent two rounds confirming it
the expensive way:

> *"If an agent knows it left work undone and hands back anyway, no note can fix that; only a
> stopping condition it cannot self-certify past."*

The probe's model of "done" is **"the code works"**. It is not confused about where the doc is
(round 012), and not ignorant of the doc's contents (round 013) — it read the section and quoted
it. It simply does not count the doc as part of the task.

The only intervention that reliably changes that is a check the agent **cannot self-certify
past** — i.e. a failing test. And **probes are forbidden from running tests**, by construction, in
every round of this loop. So:

**T002's convention score is measuring a limit of the probe harness, not a defect in this
codebase.** A real user's model would run the suite, hit the guard, and fix it. Round 008 said the
scores understate readiness; rounds 012 and 013 have now bounded *by how much* on this axis:
**on the docs-and-tests tail, the measurement is not informative at all**, because the one
mechanism that works is switched off for probes.

This does not make the loop worthless — navigation and correctness are measured honestly, and
this round proved round 011's unfreezing fix worked. It means **convention should stop being
scored as a codebase property on tasks whose only gap is the tail**, and the loop should say so
rather than spending a third round attacking it.
