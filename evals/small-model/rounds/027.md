## Fix — the breadcrumb guard was only walking the TOP level of scripts/

Chasing why the probe never named a doc, I found the file it edited has **no `# Docs:` breadcrumb at all** —
and neither does almost any file in `scripts/cloud/`. The convention's guard passes anyway, and the reason
is a one-line defect:

```gdscript
var dir := DirAccess.open(SCRIPTS_DIR)
for f in dir.get_files():        # <- top level only, no recursion
```

**So every file in a SUBDIRECTORY escaped the convention entirely:** `scripts/cloud/` (13 files, **12 with
no breadcrumb**) and `scripts/multiplayer/` (5, which happen to comply voluntarily). Both directories were
created **after** the convention landed — which is precisely the decay the guard's own header warns about:

> "a convention that only holds for the files that happened to exist on the day of the sweep decays from
> that day onward. This is the half-fix that has cost this project two rounds already: 82 scripts were given
> breadcrumbs with nothing requiring the 83rd to have one."

The guard was written to stop exactly this, and a non-recursive scan quietly re-opened the hole for every
new directory. That is why T012's probe had nothing pointing it at `features/cloud-save.md`.

**What I changed:**

1. **Made the scan recursive**, reusing the `_gd_scripts_under` helper already in the file, with the reason
   and the decay quote written in so it is not "simplified" back. Added a sanity floor
   (`assert_gt(out.size(), 100)`) so a broken walk fails loudly instead of vacuously passing.
2. **Checked the baseline could not accidentally widen.** `BREADCRUMB_BASELINE` matches on **basename**, so
   a subdirectory file sharing a name with a baselined top-level file would have become silently exempt. I
   verified **no such collision exists** before flipping the switch, and recorded that in the comment.
3. **Added the 12 missing breadcrumbs** to `scripts/cloud/`, each naming a real doc and 1–2 **existing**
   primary test files. I derived the mapping by checking which test files actually reference each class
   rather than guessing, and respected round 005's cap (name the primary tests, not a haystack).
4. **Fixed the failure message**, which printed `scripts/<basename>` — now wrong for a subdirectory file, and
   it would have sent a reader hunting in the wrong place. It now names the full path.

**Durability (§2.6a): sweep + ratchet, and the ratchet is the point.** The 12 breadcrumbs are the sweep; the
recursive scan is what makes the 19th file — and the first file of the *next* new subdirectory — comply by
default. Note this is the second time in this loop that a guard has been found not to cover what it claimed:
round 024's `expected_tests` was too narrow, and now this. **When a guard exists, check what it actually
walks before trusting it.**

**Validated in both directions, twice:** green on main (7 tests); a throwaway breadcrumb-less file under
`scripts/cloud/` now fails with `res://scripts/cloud/tmp_crumb_probe.gd has no # Docs: header breadcrumb`,
