#### Fix 2 — unfreeze the assertion; give the framework the API that makes it testable

- **`tests/headless/test_pause_menu.gd`** — renegotiated. It now asserts the two things that are
  actually invariant: the cursor lands on `first` **when there is nothing remembered**, with that
  precondition *established* (`MenuNav.forget()`) rather than assumed from file order; and a new

- **`scripts/menu_nav.gd`** — added `MenuNav.of(root)` (the live nav on a root) and `forget()`

**A design bug found while proving the fix, worth recording because it nearly shipped.** I first
resolved the remembered row at *show* time, to stop a stray focus event hijacking the restore.

fired by the time `visibility_changed` runs, so resolving early misses the row the player just
moved to. Reverted to late resolution and fixed the *test's* precondition instead — the order
dependence was the test's, and moving it into the framework would have been the wrong home for
it. The comment in `_on_root_visibility` now records both constraints so the next person does not
retry the same "improvement".
