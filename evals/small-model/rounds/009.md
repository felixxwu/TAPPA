## Fixes applied (main checkout, no commits)

### Fix D — give "lift-off" an honest name (cause 5)

`scripts/engine.gd` gains `const THROTTLE_DEADBAND` and a static
`is_lifting_off(throttle) -> bool` — the searchable answer to "has the driver lifted
off", throttle position ONLY. `combusting` keeps its name (it is honest: "the engine is
making torque") but its hoist comment is replaced by an explicit three-state table
saying in as many words that `not combusting` is ALSO true mid-gearchange and under fuel
cut. Its body is now `not lifting_off and shift_timer <= 0.0 and not fuel_cut` —
logically identical. Comments added where `friction` is computed (one term, two
customers) and at `_update_limiter` (the cut happens at WIDE OPEN throttle).

Whole-repo grep: `combusting` occurs only inside `engine.gd` (a function-local and a
private param), so no shim was needed and none was left. **No behaviour change** — both
use sites keep their exact original condition; the non-comment diff is 4 added lines and
one rewritten boolean.

Three new tests in `test_engine_logic.gd`, none pinning a tunable: lift-off is
throttle-position-only (a full-throttle engine mid-shift AND fuel-cut is NOT lifting
off — exactly what `not combusting` would wrongly claim); limiter bounce depends on the
fuel-cut friction; and coasting and fuel-cut share one friction term (relative tolerance
off a measured value, no absolute number).

**Durability: ratchet + honest limitation.** The tests fail if a future change gates the
drag on the driver being off-throttle or zeroes it under a cut. The agent flagged, and I
am recording rather than burying, that a change applied at `not combusting` — the
original trap — moves both branches together and stays green; no test can ban that
without pinning a tunable. The naming and the state table carry that part, which is
weaker than a gate and is the honest ceiling here.

### Fix A — make the invented reward channel impossible (cause 1)

`_award_any_finish_rewards() -> Dictionary` is replaced by two seams with honest types:

- `_award_any_finish_bonus_stars(combined, placed) -> int` — returns 0 today. An `int`
  return makes "invent a key nothing reads" **syntactically impossible**; the caller folds
  it into `stars_gained`, which is the only star channel `podium.gd::_show_stars` reads.
  `Save.award_stars()` moved to the caller so the seam stays pure.
- `_award_any_finish_fields(combined, placed) -> Dictionary` — for the legitimate future
  non-star reward, but now merged through `_merge_result_fields()` against a
  `const RESULT_FIELDS` allowlist. An unknown key is dropped and `push_error`'d with the
  key name AND the instruction ("return an int from `_award_any_finish_bonus_stars`, or add
  the key to `RESULT_FIELDS` and to the UI") — the failure hands back the fix rather than a
  complaint, per the round-008 lesson.

Behaviour preserved byte-for-byte while the seam returns 0, and no ledger call fires. No
double-count: `Save.complete_rally` credits the placement and returns that delta (which is
what `stars_gained` already meant), `Save.award_stars` is the documented non-rally channel,
so a bonus adds on top exactly once and `stars_gained` still equals the ledger movement —
the invariant that broke in both round 008 and round 009.

Deliberate detail: `push_error` prints `USER ERROR`, which `run_tests.sh`'s
`TEST_ERROR_PATTERN` does NOT match — so the guard announces itself in the editor and in
logs without falsely reddening unrelated runs.

Five new tests, none pinning a tunable — the bonus amount asserted is the TEST'S OWN
variable, supplied by an inner-class session that overrides the seam, and the finish is
non-podium so no authored star table is involved. One of them merges the exact invented key
from this round (`clean_run_stars`) and asserts it never lands; another asserts the
allowlist cannot drift from the result literal.

**Durability: structural impossibility (layer 1) + ratchet.** The int return removes the
failure mode rather than warning about it; the allowlist test catches drift in the dict
seam that remains.

### Fix B — give "wetness" a name (cause 2, mandatory under the three-round trigger)

`WeatherLibrary` gains `is_wet(id)`, `wet_ids()` and a single declared `WETNESS` table;
`RallyLibrary.event_is_wet(event)` is the event-layer delegate. Deliberately a separate
table rather than a per-entry key, because an omitted entry key legitimately means "lacks
that feature" — so an unclassified condition would silently read as dry, which is the exact
bug being fixed.

**A finding that changes how I read three rounds of failures:** the fix agent grepped and
found there were **no pre-existing wetness decisions anywhere in the codebase** to route
through the new predicate. The weather system is entirely table-driven (`grip_mult`, `look`,
`road_tint`, `wind`, `headlights` are all entry keys), so every failing probe was
*introducing the first one*. That is why three rounds in a row produced a rain-only
comparison: there was no correct example to copy, only seven bare string constants.

Guard: `test_every_condition_is_classified_wet_or_dry` iterates the library and fails if any
id lacks a `WETNESS` row, so an eighth condition cannot ship unclassified. It asserts only
that each id is ANSWERED, never which ids are wet — that is a design choice and CLAUDE.md
forbids pinning it. Subject list derived from the library, never hardcoded.

**Two edits the agent correctly refused to make (it did not own the files), applied by me:**

- `scripts/game_config.gd::fill_tire_context` now seats `ctx["is_wet"] =
  WeatherLibrary.is_wet(weather)` alongside the raw id, with a note at the point of use
  saying a wet axis must read the bool and never compare to `"rain"`, because `storm` is wet
  too. **This is where the observed bug actually lands** — the three failed probes all wrote
  their comparison here.
- `scripts/region_library.gd`'s RALLIES template: the `map_pos` prose is replaced by
  "paste the result of `RallyLibrary.suggest_map_pos("<region_id>")`".

**Durability: ratchet + structural.** The classification guard covers conditions that do not
exist yet; `ctx["is_wet"]` means the correct comparison is the one already sitting in the
context dict.

### Fix C — make `map_pos` computable instead of English (cause 4)

`RallyLibrary` gains `MIN_PIN_SEPARATION`, `map_pos_is_free(pos)` and
`suggest_map_pos(region_id)`, which anchors on the first rally in that region, walks a
deterministic golden-angle spiral, and returns the first pin that is in bounds, clear of
every pin and HQ with a 1.1x cushion, and inside the anchor's reveal radius.

**A function, not a coordinate list, and the reason matters:** a list of "currently free"
coordinates is itself a sweep — it rots the moment a pin moves or `map_reveal_radius` is
retuned. `suggest_map_pos` re-derives from `all()` and live config at call time, so it
cannot go stale. The guard test now reads `MIN_PIN_SEPARATION` from `RallyLibrary` instead of
keeping its own copy, so helper and guard can never disagree, and its failure message prints
a legal substituted pin — paste-the-fix, the shape that worked for the reachability guard.

Verified offline over the parsed table (38 rallies): **zero illegal pins today**; no authored
value changed.

**Durability: ratchet.** The constraint is now executable from the authoring site.
