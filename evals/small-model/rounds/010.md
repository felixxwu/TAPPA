## Fixes applied (main checkout, no commits)

### Fix E — retract my own round-009 guard, which forbade a sanctioned feature (highest priority)

`test_coasting_and_fuel_cut_share_one_friction_term` asserted that coasting decel EQUALS
fuel-cut decel. T006's probe implemented lift-off braking correctly — gated on the
`is_lifting_off()` predicate round 009 added precisely so this could be written — and the
guard went red at a ratio of exactly the new gain.

An independent grader adjudicated this against me and was blunt: the assertion held only
while the knob equals 1.0, so it pinned a *relationship between authored tunables*, which
`CLAUDE.md` explicitly forbids. Worse, the comments beside the seam actively instruct an
implementer to do the thing the guard forbade. **A guard that fails the sanctioned solution
is over-specified.**

Replaced by `test_a_fuel_cut_drags_the_revs_down_on_its_own_terms`, which asserts what I
actually cared about — the limiter has no drag of its own, so the fuel-cut path must keep
pulling revs down whatever anyone does to lift-off feel — and permits any gain. The comment
records why the old assertion was wrong, so it is not re-derived later. 22/22 green.

**The lesson, stated plainly because it cost a round:** §2.6a's pressure to attach a ratchet
to every fix can produce a test that pins the ABSENCE of a feature. A durability ratchet must
assert an invariant that survives the codebase's own sanctioned changes; if a live task in the
bank would redden it, it is not an invariant, it is a freeze.
