### T009 — round 006's registry repair is confirmed working (3/1/0/2 → **3/2/2/1**)

The grader verified the claim rather than accepting it: the probe touched **only**

The known trap recurred in full, though: the arm matches the bare string `"rain"`

channel arm to call and one hardcoded literal is the path of least resistance.

## Failure causes (taxonomy)

1. **The obligation must live AT THE EDIT SITE, not at the top of the file (×3 —
   T004, T009, T003; and it retro-explains rounds 003–006).** Two graders reached
   this independently. Breadcrumbs sit at line 3 of files thousands of lines long,
   while edits land at lines 187, 212, 228, 277, 3302 — and these agents navigate by
   symbol search, so they never scroll past the breadcrumb. T004 is the proof: its
   edit-site comment named the bound *tests* as the follow-up and stopped, and the
   probe "did precisely what the comment enumerated" — updating the test and not the
   doc the comment never mentioned.
2. **Docs transcribe lists that code already owns (×2 — T004, T003).**
   `features/hud.md` hardcodes the `DEBUG_READOUT_NODES` membership AND the
   per-element test name; `features/regions.md` hand-maintains "the game ships six".
   Code and test are bound to a single source of truth; the doc is an unbound third
   copy, so the doc is exactly what rots.
3. **A guard test whose message prescribes the damaging shortcut (×1 — T003).**
   The reachability guard says `give a rally "region": "<id>"`, and tag-set
   membership cannot tell authoring a home from stealing one.
4. **No `WeatherLibrary.is_wet()` predicate (×1 — T009).** Nothing correct exists for
   a channel arm to call, so a bare `"rain"` literal is the path of least resistance
   and `"storm"` — the wettest weather in the game — silently gets nothing.
5. **A disabled state that is structurally terminal, and no named apply-owner
   pattern (×1 — T007, REPEAT of round 003, identical).**
6. **The clean-run signal is computed and thrown away (×1 — T008).** Round 005's own
   `took_damage` local carries a comment saying it is the answer to this question,
   and nothing persists it to resolve time — **my comment promised what the code does
   not provide**.
7. **A test helper that is a misuse magnet, with a neighbour teaching the wrong
   pattern (×1 — T008).** `_start(rally_id, model)` positionally shadows
   `start_rally(rally, owned, skip_gen)`; three idioms for the same two operations
   within ~40 lines.

### Fix A — the obligation moves to the edit site, and docs stop transcribing (causes 1 + 2)

The dominant cause, with a mechanism finally identified rather than guessed at.

- **`scripts/hud.gd`** — the `DEBUG_READOUT_NODES` block now says editing the list is a
  **three-part change** and names the two docs by path. This is the precise gap the
  grader found: the old comment named the bound *tests* as the follow-up and stopped,
  and the probe "did precisely what the comment enumerated". Two stale prose
  enumerations of the membership in that file now point at the constant instead.
- **`scripts/region_library.gd`** — a four-part note at `REGIONS` itself, including the
  one the guard test caused: **prefer adding a rally over retagging one**, spelling out
  that a retag goes green while silently restyling a rally whose map position and
  authored weather belong to its old region.
- **`scripts/upgrade_library.gd`** — a three-part note at the tyre-parts block, naming
  **both** docs that describe the slot (only one ever gets updated) and the
  `unlocked_by_rally` parity question.
- **`features/hud.md`** — stops transcribing the membership list and the per-element
  test name, and points at the constant instead, saying why: *"a second copy of a list
  is a second thing to rot, and it did."*

**Durability (§2.6a): ratchet.** New `tests/headless/test_region_docs.gd` (2 tests):
every authored region must be mentioned in `features/regions.md`, and any region count
the doc states must match `REGIONS.size()`. Adding a region now forces a doc edit in
the same change. It deliberately does not pin what the doc *says* about a region —
that would be a second thing to update.

### Fix B — the speed-lines apply-owner (cause 5, failed identically twice)

New `scripts/speed_lines_setting.gd`, mirroring the `fps_setting.gd` exemplar:
`SETTING_KEY`, `default_enabled()`, `resolve()`, and `apply(tree, on)` which persists
and pushes to every live overlay in a group. `speed_lines.gd::_ready` no longer
early-returns — it binds `_mat` unconditionally, then applies through a new public
`set_effect_enabled(on)` that is **idempotent and correct in both directions, before or
after `_ready`**. The disabled state is no longer terminal.

The `Config.data` drift bug is designed out: `apply()` is the only sanctioned write
path, and the authored default is documented as read-only at the point of use, with
`test_apply_never_writes_the_authored_default` enforcing it. Seven new tests including
`test_can_be_enabled_after_being_constructed_disabled` — the exact bug.

**Durability (§2.6a): structural + named pattern.** The seam makes the failure
unwritable; `features/menus.md` gains an "every persisted setting owns its key in its
own module" section naming `fps_setting.gd` as the exemplar, placed **in the
Settings-page section** rather than at the top of the doc, per this round's own cause 1.
The new module also faced the round-005 breadcrumb ratchet and carries its header.

### Fix C — the reward seams and the misuse magnet (causes 6 + 7 + 3-round escalation)

- **The damage signal is persisted.** `_took_damage_this_rally` is latched where damage
  happens (in `report_event_result` off `took_damage`, so an unbound car still counts,
  and in `report_wreck`, which never routes through it), reset in `start_rally`, exposed
  as `took_damage_this_rally()` and as a `"took_damage"` result field. **My round-005
  comment now points at something that exists.** A note at the `_apply_field_repair()`
  call says outright that HP is not a damage oracle and why.
- **The seam the prose asked for now exists.** `_resolve_results` splits into
  `_award_podium_rewards(...)` and `_award_any_finish_rewards(...)`, the latter called
  after the gate closes and currently returning `{}` — so behaviour is byte-identical
  and there is now an obvious, named home for an any-finish reward. The clean-run bonus
  itself is deliberately NOT implemented; it stays the eval task.
- **The misuse magnet is defused.** `_start` → `_grant_and_start(rally_id: String,
  model_id: String = "fx_light_rwd")`, both parameters typed, name stating that it
  grants a car — across **43 call sites**. The neighbour test that hand-rolled
  grant-then-`start_rally` now uses the helper. `_capture_finish()` returns
  `Array[Dictionary]` and all three unboxing idioms collapse to one `_finish_result(box)`.
- Four new tests for the damage signal; three feature docs updated.

**Durability (§2.6a): structural.** A typed signature and a name that states its effect
cannot be misused the way the old one was; the seams make "where does this go" answerable
without prose.
