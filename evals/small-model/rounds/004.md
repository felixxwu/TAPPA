## The defect, precisely

Adding a third surface axis (wet, gravel, ice…) to the tyre-compound model
required, in order, with no compiler or test help for any omission:

1. a new `@export` in `game_config.gd`
2. widening `GameConfig.tire_surface_mult`'s **signature** (4 positional args)
3. all 3 call sites in `drivetrain.gd::_surface_at`
4. the call site in `lap_time_model.gd::_surface_grip`
5. `car.gd::_apply_physics_spec`'s neutral re-seed
6. `car_performance.gd::merged_meta`'s carry list

…plus ~6 direct calls in `tests/headless/test_drivetrain.gd` that a signature
change breaks at compile time (losing the whole file), plus rewriting the note
itself. Step 1 alone compiles and applies and does *nothing* — the part reads as
fitted and no gameplay test fails.

## The fix (single layer-1 restructuring)

A **registry table** replaces the enumerated checklist. `GameConfig.TIRE_SURFACE_AXES`
is the one place that knows which per-surface multipliers exist; every consumer
derives from it instead of naming the fields.

Files changed — see "What changed" below for the itemised list.

Adding a surface axis is now: **one row in the table, one `@export` beneath it,
one `match` arm next to the table** — three edits, all inside `game_config.gd`,
within ~20 lines of each other. No consumer file changes. No signature changes.
Nothing in `tests/` changes.

### Layer coverage (§2.6)

- **Layer 1 (authoring) — YES, primary.** The 6-site cross-file edit no longer
  exists; the sites are collapsed into one adjacent block. The failure mode
  "widen the signature, break the test callers" is gone because there is no
  per-axis signature any more.
- **Layer 2 (runtime) — YES.** `_tire_axis_value` `push_error`s when a table row
  names a property `GameConfig` does not have, and `_channel_weight` `push_error`s
  on a channel with no blend rule. Both previously applied a silent neutral 1.0
  forever.
- **Layer 3 (test) — YES.** `tests/headless/test_tire_surface_axes.gd` guards the
  registry **both ways**: every row's field must be a real `GameConfig` property,
  and every `tire_*_grip_mult` export must have a row. The second direction is the
  round-002 silent-no-op class, now impossible to ship rather than merely warned
  about.
