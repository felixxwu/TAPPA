### This sharpens round 013's refutation into something usable

Round 013 refuted *"a probe updates the doc it had to read"* — its probe read
`menu-navigation.md`, cited it by line range, and edited nothing. This probe read
`save-persistence.md` and **did** edit it, thoroughly. Both facts are real, so the hypothesis was
not merely wrong, it was **the wrong shape**. The version that fits all the data:

> **A probe updates a doc when its change makes a statement in that doc FALSE. It does not
> update a doc merely because its change is relevant to that doc.**

Every observation fits: round 010's T009 and T006 probes changed systems whose docs described
them mechanically; this probe falsified a specific sentence and rewrote exactly that sentence;
T002's probe *used* a documented capability without invalidating any claim, and edited nothing.

**Actionable, and it inverts the usual advice.** A doc full of capability descriptions ("you can
pass `remember = true`") will not get maintained by these agents. A doc that states **falsifiable
facts about the current system** ("there is no such counter", "these three fields exist") will.
Round 003 wrote that "no counter exists" sentence as a *warning*; it turns out to have also been
a **tripwire**, and it worked as one eleven rounds later.

### Fix — a ratchet for the undeclared-key defect

`tests/headless/test_save_manager.gd` gains
`test_every_persisted_key_written_is_declared_in_the_default_profile`:

- **Derives its subjects from the source** — regexes every `profile["key"] =` / `p["key"] =`
  write in `save_manager.gd` and requires each to appear in `Save._default_profile()`. A field
  added tomorrow is covered with no edit to the test.
- `PROFILE_KEY_WRITE_EXEMPT` holds exactly one entry, `schema_version`, which the migration chain
  writes as its own bookkeeping.
- The failure message explains **why it matters rather than restating the rule**: `_migrate()`
  backfills from `_default_profile()` alone, so an undeclared key is missing from every fresh and
  every migrated profile until something writes it, and a `.get(key, 0)` reader hides that
  completely. It names `stars_earned` / `cloud_revision` as the shape to copy.

**Layers.** Layer 3 (test time) primarily. Layer 2 skipped — the broken state is a *missing* key,
which by construction cannot announce itself at runtime. Layer 1 not attempted: making the field
impossible to write undeclared would mean routing all profile writes through a typed accessor,
which is a much larger change than this round can carry honestly.

**Durability — RATCHET.** Filesystem/source-derived, empty violation set on main, one named
exemption.
