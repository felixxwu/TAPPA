## THE ROUND'S REAL FIND — a guard that covered PHRASINGS while reading as if it covered the CONCEPT

Diagnosing the failure, I checked what round 010's count guard actually matches: `" N part"`, `" N tyre"`,
`" N tire"`. All **word-order shaped**. So:

- Round 042's probe wrote **"three tyre compounds"** → caught.
- **Round 040's probe wrote "and the tyre slot three — `Stock` / `Snow` / `Race` / `Gravel`" → NOT caught.**
  Same defect, different word order, and it sailed through the round I called a clean solve.

**And the trap was in main the whole time.** The doc read *"and the tyre slot two —"*, a count sitting in
prose the old guard could not see. That is why two probes in three rounds wrote a count there: **the doc
invited the edit.** A probe adding a compound finds a number describing the slot and updates it, which is
precisely the fix the guard's message forbids.

Three fixes, layered:
1. **The invitation removed (layer 2, structural).** `upgrade-catalogue.md:433` no longer states a count —
   it now reads "the tyre slot reads `Stock` alongside a label per compound". There is no number left to
   update. My first rewrite attempt said "the tyre slot one per compound" and **my own widened guard caught
   my own edit**, which is the guard working on its author.
2. **The guard widened (layer 1).** `" N compound"`, `"slot N "` and the em-dash variants now match too,
   with a comment recording both phrasings, the rounds they came from, and the instruction to widen again
   rather than assume the concept is covered. Validated in both directions: **main green; on the probe's
   tree it now catches TWO lines (175 and 435) where the old guard caught one.** Line 435 is the round-040
   phrasing — so the widening demonstrably closes the hole that let a non-clean solve read as clean.
3. **Point-of-use line (layer 4)**, in the tyre note's part 2: name the part, never write a count; updating
   a number you found in the prose is the WRONG fix, deleting it is the right one. Note now 51 lines.

**§D4 generalisation:** the guard is slot-blind — it already scans `turbo`, `aero`, `gearbox`, `nitrous` and
`weight` prose, so it serves every catalogue-addition task, not just tyres. The doc fix removes a trap any
part-adding probe would have hit.
