## Why this task is interesting beyond coverage

Its central trap is an **anti-clutter rule whose RATIONALE is written down**, not just its instruction. The header
says every pin used to carry its name and that this "turned the full map into a wall of overlapping capitals with
the roads invisible underneath — the map stopped answering 'where do the roads go', which is the only reason it
exists."

Every lever this loop has confirmed so far concerns *what* to do — a rule at the edit site, a correct sibling to
clone, a contradicted statement to repair. **This tests whether a documented WHY generalises to a new decision the
rule does not literally cover.** The rule is about *names*; the task is about *stars*. Nothing says "and don't put
stars on every pin either".

### This is my authoring error — the second in three rounds, and the same class as round 017's

I checked `overworld_map.gd` and correctly found no star data. **I never checked the other surface that has map
pins.** The HQ has a diegetic 3D map table whose pins have a floating readout box, and that box has taken a
`stars` parameter all along. "its map pin" is ambiguous between the overworld map and the HQ table, and one of the
two already had the feature.

Round 017 found T007 "already half-implemented"; round 033 finds T014 already implemented on one of two surfaces.
Two instances make a rule:

> **Before authoring, enumerate EVERY surface the request could mean and check each one — not just the one you
> had in mind.** A grep of the file you are thinking of proves nothing about the file you are not.

### What is scoreable, and what is not

**Not scoreable: correctness and convention.** The rubric was written assuming the feature was absent; grading a
probe against it would be measuring my mistake. Those axes are void for this attempt.

**Scoreable, and worth recording: navigation 3, plus one real behavioural finding.**

- **Navigation 3.** It found the correct surface unaided — `hq.gd::_build_readout_box`, in a 4,750-line file —
  and understood the existing plumbing well enough to describe the star row accurately in its report.
- **The finding: it duplicated rather than reported.** Its own summary lists "Visual star row (gold filled stars +
  dim unfilled stars)" as item 3 of what the box shows, and its new numeric label as item 2 — so **it saw the
  existing star row and added a second display of the same number anyway**, describing the result as making it
  "immediately obvious … without needing to count visual stars". It never said "this already exists".
  That is a distinct small-model failure mode the loop has not recorded: **given a request that is already
  satisfied, it adds a redundant duplicate instead of reporting completion.** Round 017's T007 and round 018's
  T003 both involved pre-existing seams, but in both the probe still had real work to do; this is the first case
  where the right answer was "nothing to do" and the probe manufactured work instead.

**Neither void burns an attempt** (`MAX_ATTEMPTS` untouched): the first was an API outage, this one is a defective
task.
