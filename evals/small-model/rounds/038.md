## Fixes — one structural, one making an instruction checkable

**1. Collapsed the three countdown-arm sites into `_arm_countdown()` (layer 1).** `_countdown_left` was assigned
identically at three places (STAGING setup, direct COUNTDOWN setup, `begin_countdown`); the probe added per-countdown
state and reset it at two. §2.6 is explicit that a checklist past ~3 sites *is* the defect and the answer is to collapse
the sites, so rather than adding a note listing them:

```gdscript
# THE ONE PLACE A COUNTDOWN IS ARMED. Three call sites reach here … which is why this exists
# rather than three copies of the assignment: **any per-countdown state belongs in here.** An
# attempt … reset it at two of the three sites, so re-arming through the third within the first
# second silently swallowed the first cue. Put it here and that cannot happen.
func _arm_countdown() -> void:
	_countdown_left = _cfg().stage_countdown_seconds
```

Behaviour-identical (the same assignment, now once), and it makes the missed-reset class **unwritable** rather than
warned about. **Durability (§2.6a): tier 2, a structural impossibility** — there is no longer a second site to forget.

**2. Made "higher hz" checkable (rounds 019/020's lesson).** Part 1 said `Audio.play_beep(<higher hz>)` for GO — a
placeholder with no reference point, so a probe could satisfy its *form* with 800.0 while inverting its *intent*. Now:

> "**'HIGHER' IS CHECKABLE, SO CHECK IT:** the tick uses `GameConfig.sfx_beep_frequency_hz`, which is 880.0 today, so
> a GO pitch must be ABOVE that number — an attempt passed 800.0 and commented it as 'higher' … Re-read the export
> rather than trusting this figure; it is an authored value."

The closing caveat matters: quoting an authored number in a comment is exactly the staleness trap §2.6 warns about, so
the note tells the reader to re-read the export rather than trust it. **Durability: tier 4, a point-of-use note** — a
guard is unavailable because the correct relationship is between a call-site literal and a tunable, and asserting it
would pin the tunable, which `CLAUDE.md` forbids.

**Not fixed: the docs.** Part 3 already names both files as a numbered obligation with its reason attached and was
ignored anyway. That is the sixth doc mechanism to fail; §2.6 forbids a seventh attempt, and round 032's standing
conclusion is to use a guard instead.
