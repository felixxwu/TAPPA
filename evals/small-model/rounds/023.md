## A cross-round synthesis, found while the probe was out — round 022's negative result already has an answer, and this loop found it in round 008

Round 022 settled that a note cannot make a probe **author** a new test, and framed that as "the loop's
floor". Investigating T004's site shows that framing is incomplete, and the completion comes from the
loop's own history.

**Three facts that only make sense together:**

1. **Round 007's T004 probe DID rewrite a test** — the bank's note says so explicitly, and that the
   grader checked it was not gutted. So a probe *will* touch a test.
2. **What it touched was an EXISTING test whose NAME identified the contract it was changing**
   (`test_gear_label_is_part_of_the_h_gated_debug_readout`). That is **reconciling** a test, not
   authoring one.
3. **That test no longer exists.** Round 008 deleted it and its siblings on purpose, and
   `tests/headless/test_hud.gd` carries an eighteen-line explanation of why:
   - they **pinned a product choice** (which labels sit behind the dev toggle is a designer's decision,
     and `CLAUDE.md`'s "never test a value someone may reasonably change" covers membership too);
   - they **made the constant's own promise false** — the note above `DEBUG_READOUT_NODES` says moving an
     element is a one-line edit, and with a hand-named test per element it was one line plus a rewrite
     inside a 550-line file, "and two separate eval probes duly did the first and skipped the second".

   The real contract is now covered by **two membership-driven tests that iterate `DEBUG_READOUT_NODES`
   and need no edit when it changes.**

**So the distinction round 022 was missing is authoring vs reconciling — and the right response to the
floor it found is not to push harder on the obligation, but to DELETE it:**

> A probe will not author a new test. It will sometimes reconcile an existing named one — but a named
> per-element test is itself a defect (it pins a product choice and falsifies the one-line-edit promise).
> **The durable answer is a membership-driven test that needs no edit at all**, plus a separate machine
> guard for the docs. Round 008 reached that conclusion for the HUD and it is the general form of the
> answer to round 022's negative result.

That is §2.6a's "prefer deleting an obligation over describing it" applied to tests specifically, and it
means round 022's finding is **actionable after all**: where the loop has been trying to make probes
write tests, the fix is to arrange that no new test is owed.

**Consequence for T004 as it stands today:** the correct answer is a one-line `DEBUG_READOUT_NODES`
membership edit plus `features/hud.md` — the tests adapt themselves, and `test_hud_docs.gd` already
guards the doc. This is the leanest obligation set of any task in the bank, which makes the probe's result
a clean read on whether a one-line edit plus one doc is reachable.
