- **Catalogue fields for richer rally classes** (from `one-map-four-corners.md`) — following the standing rule in `features/rally-roster.md` (when a rally wants to group cars by a property the catalogue doesn't record, ADD the property rather than approximating it with a proxy):
  - **`aspiration`** (NA / turbo / supercharged) on `EngineLibrary.ENGINES` — unlocks "naturally aspirated only" classes. Belongs on the engine, not the car, so an engine swap changes eligibility (same reasoning as `displacement_l`).
  - **`era` / `decade`** on `CarLibrary.CARS` — unlocks period events. A body property, so it belongs on the car.
  - **A genuine kei event isn't viable yet** — `car_type: "kei"` picks out a single car, so `hc_lakeside_kei` is authored as a Japanese national class instead. Viable once the roster carries more kei entries.
  - Each new restriction field needs **two** text surfaces and it's easy to add only the first: a branch in `RallyLibrary.ineligibility_reason` (why a car was rejected) *and* an entry in `hq.gd._restriction_text` (how the restriction reads in the detail panel). Missing the second means the restriction is silently absent from the rally description. Use `./report_eligibility.sh` when authoring (2-3 eligible cars per rally, hard floor of 1).
