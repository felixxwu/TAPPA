# Phase 2 — A neutral data format: implementation plan

**Depends on:** the Hafren-only cleanup (done 2026-11-28). Nothing else: spec "Dependencies" lets Phase 2
run alongside Phases 0 and 1. This file plans steps 2.1–2.3 of `todo/2026-11-27-rust-native-migration.md`
("Phase 2 — A neutral data format", and the `assets` row of "Crates"); tick them there as they land.
Phase 3 (the viewer) is the consumer, so the formats below carry what its "Renderer" section needs:
decoded pixels, texture arrays per tree species, the shared atlas, vertex arrays to pull by index, LOD
index lists with Godot's `edge_length` (for the `mesh_lod/lod_change/threshold_pixels=4.0` rule), and the
`[shader_globals]` values.

The user is away. Each step is split into **Build now** (agents) and **Needs the user**. The work packages
(WP) are ordered so each wave's packages touch disjoint files and can go to parallel Sonnet agents.
Subagents don't run tests (CLAUDE.md); the parent runs the targeted set listed at the end.

**No Rust toolchain on the Mac.** Agents write the Rust blind; GitHub Actions (ubuntu) is its compiler and
test runner. Everything Rust is reached through one script, `tools/neutral_check.sh`, that CI runs and the
user can run locally later (§4).

## 0. Corrections to the spec found while planning

- **`models/` holds only `models/spectators/spectators.glb`.** There is no cabin or rocks model. The ground
  cover tufts are built in code from the save's `coverKinds` recipes (`ground_cover.gd` → `_far_meshes`,
  `placements`), so they're exported with the built level geometry, not as models.
- **The tree tiles are already in the bake.** `LevelBake.tree_xf` is numbered tile by tile
  (`tree_tile_first`, `tree_kind`), and `LevelTrees` builds its draw buffers from that plus the
  visibility rows at run time. Exporting the bake (2.1) exports the tree tiles.
- **The cars come in through `car.tscn`,** which embeds every car body (`features/asset-pipeline.md` →
  "Car body textures"); `car.gd` → `_apply_model_material` then swaps in
  `CarLibrary.CARS[*].model_texture`. Wheels are `CarLibrary` `wheel_model` GLBs
  (`blender/mx5/wheel.glb`, `blender/f150/wheel.glb`); crowds load `blender/spectator/spectator.glb` and
  `models/spectators/spectators.glb` (`crowd.gd`). No model has a skeleton or animation.
- **Music is already neutral.** The 24 `music/*.ogg` import as `oggvorbisstr` with `loop=false`, so the
  Ogg bytes are what plays. They're listed in the index and copied, not converted.
- **Shaders aren't data.** Each `.gdshader` becomes a WGSL pipeline in Phase 3. Only the
  `[shader_globals]` block of `project.godot` (`hl_pos`, `hl_dir`, …) is exported, as JSON.
- **Godot's bake key can't be reproduced outside Godot.** `LevelBake.key_of` is
  `JSON.stringify(d).md5_text()` of the parsed save minus eight keys, and Godot's number formatting in
  `stringify` isn't JavaScript's. So the neutral file gets its own key (§1), and the Godot key rides in
  its header for a consistency check.
- **`hafren_5km.json` isn't fully neutral:** it embeds WebP images (`heightWebp`, `coverWebp`,
  decoded by `LevelData.unpack` and `GroundCover.decode_cover`) and base64 `treesBin`. Rust has to decode
  them, so their decoded bytes go in the parity manifest too.
- **VRAM-compressed textures are 12, not "a few":** the ten car-body textures under `blender/`
  (`compress/mode=2`), `textures/grass.jpg` and `textures/sky_field.png`. Each has two imported variants,
  `path.s3tc` and `path.etc2` in its `.import`. The other textures are `compress/mode=1` (lossy WebP, the
  `[importer_defaults]`) or `0` (lossless).

## 1. Shared design

### One container for every neutral file

The same shape `tools/bake_buildings.js` already uses for `.buildings.bin` (`LevelBuildings.parse_bin`),
plus compression per section:

```
u32 LE   header length H
H bytes  header: UTF-8 JSON (JSON.stringify(h, "", true, true): sorted keys, full float precision)
then, in header.sections order, each section stored as:
u32 LE   raw size
...      one zstd frame of the raw bytes   (header.sections[i].bytes = 4 + frame size)
```

A section is exactly what `LevelBake._zip` already returns, so the bake's existing blobs drop straight in.
Every number array inside a section is little endian. Header `format: 1`; a change that old readers
can't read bumps it. No magic number, no offsets table, no alignment: sections are read in order.

- **Godot writer:** new `scripts/neutral_file.gd` (`class_name NeutralFile`), about 30 lines:
  `const FORMAT := 1`, `static func write(path, header: Dictionary, sections: Array) -> Error` where
  `sections` is `[[name, zipped_bytes], ...]`, and `static func zip(raw)` (moved from `LevelBake._zip`,
  which then calls it).
- **Rust reader:** `crates/assets/src/container.rs`: `read(bytes) -> (serde_json::Value, Vec<(String, Vec<u8>)>)`.
  zstd decoding with `ruzstd` (pure Rust, so it builds for WebAssembly later).

### The parity manifest

Both sides print the same text file; CI `diff`s them. Lines are
`<file>\t<field>\t<value>`, sorted, where `value` is the SHA-256 hex of the field's decoded little-endian
bytes, a decimal int, or a float as the hex of its 8 f64 bytes (so float formatting never differs).

- **Godot's** comes from the in-memory data loaded the normal way (`LevelBake.load_fresh`, `load()` of a
  texture, `instantiate()` of a scene), never from re-reading the neutral file. Hashing with
  `HashingContext` (native, so hundreds of MB hash in seconds).
- **Rust's** comes from decoding the neutral file (`sha2` crate).
- So "the decoded data equals Godot's in-memory data" (the Phase 2 exit) is literally `diff` exiting 0.

### The neutral bake key (2.2)

New `tools/neutral_key.js` (node, stdlib only; node is on the Mac and on the ubuntu image):
`md5(JSON.stringify(save minus KEY_IGNORES)) + "-v" + BAKE_VERSION + "-n" + NeutralFile.FORMAT`.

- `KEY_IGNORES` and `BAKE_VERSION` are read out of `scripts/level_bake.gd` by regex, and `FORMAT` out of
  `scripts/neutral_file.gd`, the way `publish_bake.sh` greps `level_path` out of `game_config.gd`, so
  there is one source for each.
- That needs one refactor: `LevelBake.key_of`'s eight `erase` calls become
  `const KEY_IGNORES := ["coverKinds", "logPiles", "fences", "spectators", "teleports", "shops", "rallies", "biomeRle"]`
  and a loop. `key_of`'s output is unchanged, so no rebake.
- It's a different hash from Godot's key, but a function of the same content, so the two go stale together.
  The neutral header carries Godot's `source_key`, and CI checks it against `tools/bake_key.tscn`'s output.

### Where files go

- Neutral bake: `tools/levels/<name>.bake.bin`, git-ignored (`*.bake.bin`, beside `*.bake.res`), published
  to the same `bakes` release as `<name>-<neutral key>.bake.bin`.
- Everything else: `build/neutral/` (already git-ignored by `/build/`), mirroring `res://` paths
  (`build/neutral/textures/grass.jpg.tapn`), plus `build/neutral/index.json` (every file and its kind) and
  `build/neutral/godot.manifest`. Regenerated from git sources + Godot's import on demand, not published
  (§6, question 4).

### Rust workspace (smallest that fits the Architecture)

- Root `Cargo.toml`: `[workspace] members = ["crates/assets"]`, `resolver = "2"`.
- `crates/assets`: the `assets` crate of the spec's "Crates" table (no GPU, no window). Modules:
  `container`, `bake`, `texture`, `scene`, `font`, `level_json`, `buildings`, `geometry`, `manifest`. Plus
  `src/bin/asset_check.rs`: `asset_check <dir>` loads every file in `index.json` plus the level files,
  prints the manifest on stdout, and exits non-zero naming any file it can't read.
- Dependencies, pinned with `=` versions: `serde_json`, `ruzstd`, `sha2`, `image-webp`. Nothing else: no
  serde derive, no `anyhow`; errors are `String`.
- `rust-toolchain.toml` pinned to the stable the first CI run uses. `Cargo.lock` gets committed after the
  first green CI run (CI uploads it; nobody here can generate it).
- No `cargo tree` dependency guard yet: there's one crate. It arrives with `render` in Phase 3.

## 2. Work packages

### Wave A (parallel; disjoint files)

#### WP1 — Level bake in the neutral container (2.1, build now)
- **Files:** `scripts/level_bake.gd`; new `scripts/neutral_file.gd`; new `tools/neutral_export.gd` +
  `.tscn` (the driver for every export; WP4 and WP5 plug into it); `.gitignore`; new
  `tests/headless/test_neutral_file.gd`; extend `tests/headless/test_level_bake.gd`.
- **Approach:**
  - `KEY_IGNORES` refactor of `key_of` (§1). `_zip` moves to `NeutralFile.zip`.
  - `LevelBake.save_neutral(path, neutral_key) -> Error`. Header: `kind: "level_bake"`, `format`,
    `bake_version`, `source_key`, `neutral_key`, the `@export` scalars (`size, step, n, height_base,
    frame_n, tree_tile_n, vis_every`), `tree_kinds`, `spawn_nodes` as `[x, z, x, z]`, and the decode
    constants (`FRAME_RANGE, FRAME_CELL, PATCH_HALF, ALONG_PERIOD, TREE_TILE_M, VIS_KEY`). Sections: every
    name in `BLOBS`, each `_get(name)` as it is today, with an `encoding` per section in the header:
    `delta_u16_planes` (`z_heights`), `delta_i32_planes` (`z_tree_first`, `z_vis_*`), `raw`
    (the rest). The layouts are the ones `_set` decodes (`z_road`: `sx, sz, sw, sh, sa` f32, `sc` i32,
    `st` f32, end to end; `z_patches`: f32 point count then x, z pairs, per patch).
  - `LevelBake.manifest(file) -> PackedStringArray`: the scalars, then the SHA-256 of `heights`, `frame`,
    each of `sx…st`, flattened `patches`, `tree_xf`, `tree_tile_first`, `tree_kind`, the four `vis_*`
    arrays, and `decoded_row(r)` for rows `0, 1, VIS_KEY - 1, VIS_KEY, VIS_KEY + 1` and the last. The rows
    make Rust prove its diff decoding, which Phase 4 reuses.
  - `tools/neutral_export.gd`, run as
    `godot --headless --path . res://tools/neutral_export.tscn -- --bake=<save> | --assets=<dir> | --geometry=<dir>`.
    - `--bake`: `load_fresh` the `.bake.res` (refuse if stale or `is_incomplete()`), get the neutral key
      by running `node tools/neutral_key.js <save>` through `OS.execute`, then `save_neutral` beside it
      and append `manifest()` to `<dir>/godot.manifest`.
    - `--assets` and `--geometry` call WP4's `NeutralAssets.export_all(dir) -> PackedStringArray` and
      WP5's `NeutralGeometry.export(dir)`; until those land they're stubs that return nothing.
- **Tests (`test_neutral_file.gd`, bare logic, a tiny synthetic `LevelData` bake as `test_level_bake`
  makes):**
  - A written file parses: the header length is in range, the header is JSON, the sections' `bytes` sum
    to the file size, and each section unzips to its declared raw size.
  - Each bake section's bytes equal `_get(name)`.
  - `manifest()` of two bakes of the same data is equal, and changes when one height changes.
  - `key_of` ignores each `KEY_IGNORES` key and still sees a road change (extend the existing
    `test_level_bake` key test rather than writing a new one).
- **Break test:** drop `z_tree_kind` from the written sections; the Rust check fails naming it.

#### WP4 — Every other imported asset (2.3, build now)
- **Files:** new `tools/neutral_assets.gd` (`class_name NeutralAssets`, static functions only); new
  `features/neutral-format.md` (the format for every file kind, which WP3 and WP6 code against); a row in
  `todo/2026-11-28-parity-checklist.md` and `features/README.md` for it.
- **First, check headless.** `Texture2D.get_image()`, `Mesh.surface_get_arrays()` and
  `RenderingServer.mesh_get_surface()` may return nothing under `--headless` (the dummy renderer keeps no
  texture or mesh data). If so, the asset export runs under `xvfb-run -a … --rendering-driver opengl3`, as
  `tools/level_draw_calls.gd` already documents. Say which in `features/neutral-format.md`.
- **What's exported** (`export_all(dir)` walks these folders for `.import` files: `blender/`, `models/`,
  `textures/`, `icons/`, `fonts/`, `tools/levels/`, plus `materials/`, `theme/`, `car.tscn`; `addons/` and
  `docs/` are skipped):
  - **Textures** (`importer="texture"`): header `kind: "texture"`, `source`, `width`, `height`,
    `mipmaps`, the Godot `Image.Format` name, and the `.import` `[params]` that matter
    (`compress/mode`, `compress/lossy_quality`, `mipmaps/generate`). Section `pixels`: `get_image()` data,
    every mip, decompressed with `Image.decompress()` when VRAM-compressed. For the 12 VRAM textures, also
    sections `blocks.s3tc` and `blocks.etc2`: load each `path.s3tc` / `path.etc2` `.ctex` named in the
    `.import` (`CompressedTexture2D.load`) and store its image data as is, with its format name. Rust never
    decodes blocks; the GPU does.
  - **Scenes** (`importer="scene"` GLBs, and `car.tscn`): walk the instantiated tree for
    `MeshInstance3D`. Header `kind: "scene"`: `nodes` (`[{path, transform: 12 floats relative to the
    root, mesh}]`) and `meshes` (`[{surfaces: [{primitive, aabb, arrays, lods: [edge_length…],
    material}]}]`), each mesh once even when several nodes share it. Sections `m<i>.s<j>.<array>` for each
    present `surface_get_arrays()` entry (`vertex, normal, tangent, color, uv, uv2, index`), which is the
    data after Godot's vertex decompression, and `m<i>.s<j>.lod<k>` from
    `RenderingServer.mesh_get_surface(rid, j)["lods"][k]["index_data"]`, widened to i32.
  - **Resources** (`materials/wheel_tire.tres`, `theme/ui_theme.tres`, and every surface material):
    one generic `dump(res) -> Dictionary` over the `PROPERTY_USAGE_STORAGE` properties. Nested resources
    are inlined; textures and shaders are referenced by `res://` path. For a `Theme`, it walks
    `get_type_list()` and each type's colours, constants, font sizes, fonts and styleboxes. JSON only, no
    sections.
  - **Font** (`fonts/Jersey10.ttf`, `antialiasing=0`, `hinting=0`, `subpixel_positioning=0` in its
    `.import`): section `ttf` (the file as is), and Godot's own rasterised glyphs at 18 and 36 px
    (`UITheme.FONT_SIZE`, `TITLE_FONT_SIZE`) for U+0020–U+00FF: `TextServer.font_render_range`, then per
    size the cache textures (`font_get_texture_image`) as sections `atlas.<size>.<i>`, and per glyph in
    the header its advance, offset, size, UV rect and texture index. So the Rust UI draws Godot's pixels
    and never rasterises.
  - **Music:** `music/*.ogg` copied, listed in the index with `kind: "ogg"`.
  - **`[shader_globals]`:** `build/neutral/shader_globals.json` (name, type, value), read with
    `ConfigFile` from `project.godot`.
  - Every file appends its lines to the returned manifest: per section the SHA-256 of what Godot holds in
    memory (`get_image().get_data()`, each array's `to_byte_array()`, the LOD index bytes), and for JSON-only
    files the SHA-256 of the dumped header.
- **Tests (new `tests/headless/test_neutral_assets.gd`):** `dump` of a hand-built `ShaderMaterial` with a
  colour and a texture parameter has both, with the texture as its path; the scene walker on a hand-built
  `Node3D` → `MeshInstance3D` with one `ArrayMesh` surface lists one node and one mesh, and two nodes sharing
  one mesh list it once; a 4×4 `Image` texture's `pixels` section unzips to the image bytes. No real asset
  is named.

## 3. What the Phase 2 exit check is, concretely

The `neutral` CI job is green: `asset_check` reads every file in `index.json` plus the level's
`.bake.bin`, `.json` and `.buildings.bin`, and its manifest equals Godot's line for line. Then tick 2.1–2.3
and the Exit box in the spec.

## 4. What the user runs locally, later

Once Rust is installed (`brew install rustup && rustup-init`, then the toolchain in `rust-toolchain.toml`
installs itself on the first `cargo` call):

```
tools/fetch_neutral_bake.sh        # no Godot needed
tools/neutral_check.sh             # export with the local Godot, build, compare
```

On the Mac, the asset export runs with a window if it needs a renderer (no `xvfb`), and the Mac's manifest
is only compared against the Mac's own Godot export, never against CI's (lossy WebP decoding and LOD
generation may differ by platform).

## 5. Needs the user (deferred)

1. **Pushes to run CI.** The Rust only compiles on CI, and the agents can't push without the user's
   go-ahead (global rule: commit or push only when asked). Until then, Wave A and B land locally as
   uncommitted work and the parent reports "Rust unverified". Or run the work in the remote environment,
   where pushing to `main` is the standing rule.
2. **Publish the neutral bake once:** `tools/publish_bake.sh` (it now uploads the `.bake.bin` too). It
   needs the user's `gh` login with write access to releases; the local `.bake.res` is current, so no
   rebake is needed.
3. **Commit `Cargo.lock`** from the first green CI run's artifact (or let the parent do it with the go-ahead).
4. **Exit:** glance at `features/neutral-format.md`, since Phase 3 builds on it.

## 6. Open questions (recommended default in bold)

1. Bake sections: keep LevelBake's zstd + delta-plane blobs as they are, or store plain arrays?
   **Keep them.** Zero new encoding code on the Godot side, the file stays ~28 MB instead of ~200 MB, and
   Rust needs the delta decoders anyway to match `decoded_row`.
2. The neutral key: its own (JS, md5 of the re-stringified save) or a port of Godot's exact `stringify`?
   **Its own.** Reproducing Godot's float formatting is fragile; CI checks the two keys agree on freshness
   through the header's `source_key`.
3. Who writes the `.bake.bin`: `LevelBake.bake` itself, or a conversion from the `.bake.res` at publish
   time? **At publish time** (`neutral_export.tscn -- --bake`). The bake's visibility comes from a
   multi-window merge (`bake_level.sh`), and converting the finished resource covers every bake path.
4. Publish the other assets too, or regenerate them? **Regenerate** (git sources + Godot import, on the
   machine that compares). Publish only when a Godot-free machine needs them; Phase 6.4's importer
   replaces this anyway.
5. Textures: decoded pixels for all, blocks for the 12 VRAM textures? **Yes, both variants (`s3tc`,
   `etc2`), and Rust never decodes blocks.** Phase 3 can start on plain RGBA8 and switch to blocks per
   platform.
6. Meshes: Godot's packed vertex layout, or the decompressed arrays? **Decompressed arrays** plus the LOD
   index lists. They already hold the quantisation Godot applied, so the viewer gets the same vertices;
   it can pack its own way.
7. Fonts: rasterise in Rust, or export Godot's glyphs? **Godot's glyphs at 18 and 36 px for
   U+0020–U+00FF**, plus the TTF. Pixel-exact by construction; widen the range if a string needs more.
8. Level geometry: the whole level, or what the `hafren.rec` path builds? **The path.** It's what the
   Phase 3 viewer draws; the whole level at every LOD is Phase 4's to build in Rust.
9. WebP in `hafren_5km.json`: decode in Rust (`image-webp`) or have Godot write the decoded rasters?
   **Decode in Rust**, and fall back to Godot-written rasters only if the manifest shows a mismatch.
10. Hash: **SHA-256** (`HashingContext` / `sha2`). A hand-rolled hash in GDScript would loop per byte and
    take minutes on the textures.
11. Godot-written shader and audio data: **out of scope** beyond `shader_globals.json` and copying the
    Ogg files.
